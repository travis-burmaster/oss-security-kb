## Security Posture Summary

**Overall posture: Actively maintained, moderate-to-high historical vulnerability surface.**

Apache Kafka clients is one of the highest-impact Maven artifacts in the ecosystem (ubiquitous in JVM-based data pipelines). The Apache Kafka project maintains a public CVE list and follows coordinated disclosure via the ASF security process. Fixes are backported across active release lines (currently 3.9.x, 4.0.x, 4.1.x, 4.2.x). Seven distinct CVEs with OSV/GHSA records directly scope to this artifact, spanning 2017–2026, with severities from MODERATE to CRITICAL.

**Key observations:**
- Two **2026-dated CVEs** (CVE-2026-33557, CVE-2026-35554) indicate active, ongoing vulnerability discovery — including one CRITICAL JWT validation bypass and one HIGH data-corruption race condition.
- Recurring theme: **authentication/authorization flaws** (OAUTHBEARER bypass, PLAINTEXT session hijack, ConfigProvider privilege escalation) and **sensitive data exposure** in logs.
- Users on older branches (< 3.9.x) carry compounding unpatched exposure; the project no longer maintains branches before 3.7.x.

## Upgrade Guidance (Maintainer-Sourced)

1. **Prioritize 4.1.2 / 4.0.2 / 3.9.2** — the June/July 2026 security releases address both a critical authentication bypass and a high-severity data integrity issue.
2. **OAUTHBEARER users on 4.1.0–4.1.1**: Treat CVE-2026-33557 as emergency; JWT tokens are not validated, meaning any bearer token is accepted.
3. **All producer workloads on 2.8.0+**: CVE-2026-35554 is a race condition in `BufferPool` that can silently corrupt or misroute messages. The fix is mechanical (no config changes needed), but the impact is data integrity.
