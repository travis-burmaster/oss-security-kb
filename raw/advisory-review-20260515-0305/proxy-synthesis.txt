# OSS Security KB Review: bleach & python-jose

---

## 1. PyPI `bleach` (current: 6.3.0)

### Summary of Evidence-Backed Vulnerabilities

| CVE | GHSA | Severity | Type | Fixed In | Status in 6.3.0 |
|-----|------|----------|------|----------|-----------------|
| CVE-2018-7753 | GHSA-m9mq-p2f9-cfqv | CRITICAL | URI scheme sanitization bypass via character entities | 2.1.3 | ✅ Patched |
| CVE-2020-6802 | GHSA-q65m-pv3f-wr5r | MODERATE | Mutation XSS (noscript + raw tag) | 3.1.1 | ✅ Patched |
| CVE-2020-6816 | GHSA-m6xf-fq7q-8743 | MODERATE | Mutation XSS (svg/math + RCDATA + strip=False) | 3.1.2 | ✅ Patched |
| CVE-2020-6817 | GHSA-vqhp-cxgc-6wmm | HIGH | ReDoS via style attribute parsing | 3.1.4 | ✅ Patched |
| CVE-2021-23980 | GHSA-vv2x-vrpj-qqpq | MODERATE | Mutation XSS (svg/math + p/br + strip_comments=False) | 3.3.0 | ✅ Patched |

### KB Page Recommendation

**Create or update a `bleach` security page** documenting:

- **All five CVEs above** with fix versions, advisory links, and brief descriptions. All are resolved in the current release (6.3.0).
- **Recurring vulnerability pattern**: Four of five advisories involve mutation XSS when specific tag combinations are whitelisted. This should be highlighted as a structural risk pattern for users who whitelist `svg`, `math`, `noscript`, or RCDATA tags.
- **Mitigation guidance**: Recommend minimal tag whitelists, use of `strip=True`, and strong Content-Security-Policy headers (as noted in upstream advisories).

### Cautions

- **Project maintenance status**: bleach's upstream README (mozilla/bleach) has previously announced the project is **deprecated** in favor of alternatives (e.g., `nh3`). The KB page should note this and flag that no future security patches may be forthcoming despite the 6.3.0 release. *Verify the current deprecation status directly from the GitHub repo before publishing — do not assume based on past announcements.*
- **No open/unfixed advisories** were found in the provided evidence. However, the history of repeated mutation XSS bypasses suggests residual attack surface may exist in edge-case tag combinations.

## 2. PyPI `python-jose` (current: 3.5.0)

### Summary of Evidence-Backed Vulnerabilities

| CVE | GHSA | Severity | Type | Fixed In | Status in 3.5.0 |
|-----|------|----------|------|----------|-----------------|
| CVE-2016-7036 | GHSA-w799-prg3-cx77 | CRITICAL | Timing side-channel: non-constant-time HMAC comparison | 1.3.2 | ✅ Patched |
| CVE-2024-33663 | GHSA-6c5p-j8vq-pqhj | CRITICAL | Algorithm confusion with OpenSSH ECDSA keys (analogous to CVE-2022-29217 in PyJWT) | 3.4.0 | ✅ Patched |
| CVE-2024-33664 | GHSA-cjwg-qfpm-7377 | MODERATE | DoS via compressed JWE "JWT bomb" (analogous to CVE-2024-21319) | 3.4.0 | ✅ Patched |

### KB Page Recommendation

**Create or update a `python-jose` security page** documenting:

- **All three CVEs above**. All are resolved in the current release (3.5.0).
- **High-impact note for CVE-2024-33663**: Algorithm confusion vulnerabilities in JOSE libraries are a well-known, critical class of attack that can lead to **signature bypass and authentication forging**. Any deployment still on ≤3.3.0 should be flagged as urgent to upgrade.
- **Usage scale context**: ~41M downloads/month (per PyPI Stats) — this library is extremely widely deployed, making unpatched installations a significant ecosystem risk.
- **Cross-reference**: Note the parallels to PyJWT CVE-2022-29217 (algorithm confusion) and .NET CVE-2024-21319 (JWT bomb) for KB cross-linking.

### Cautions

- **Project maintenance concerns**: The upstream GitHub repo (mpdavis/python-jose) has a history of slow response to security issues — the 2024 CVEs were filed against version "through 3.3.0" and the fix release (3.4.0) came after public disclosure. **Check the repo's recent commit activity and open issue backlog** before characterizing maintenance status; do not speculate beyond evidence.
- **Version gap**: The fixed version per advisories is 3.4.0, but PyPI shows 3.5.0 as current. Confirm that 3.5.0 indeed includes the 3.4.0 fixes (expected, but verify via changelog at the upstream `CHANGELOG.md` link).
