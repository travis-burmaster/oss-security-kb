## Security Posture Notes

H2 is a pure-Java embedded RDBMS widely used as a fast in-memory database for unit and integration tests in Spring Boot and other Java projects. The `spring-boot-starter-test` dependency chain historically auto-configured H2, making it one of the most widely distributed Java database JARs even in projects that never use a database in production.

**CVE-2021-42392 context:** This is structurally the same attack as Log4Shell — both exploit JNDI lookups on attacker-controlled strings. H2 Console's built-in JNDI datasource-URL handling was the attack surface. Unlike Log4j, H2 Console requires explicit `webAllowOthers=true` to be reachable from non-localhost IPs; many CI/test environments enable this for convenience, making this exploitable in CI pipelines, developer machines, and any deployment that starts H2 Console without a firewall. Fixed in 2.0.206 by restricting JNDI lookups to local sources only.

**CVE-2022-23221 context:** Even without Console access, an attacker who can influence a JDBC URL string (e.g., through environment variables, configuration injection, or untrusted YAML/properties files) can execute arbitrary scripts. The `INIT=RUNSCRIPT` parameter is a built-in H2 feature intended for schema initialization; the fix in 2.1.210 restricts which parameter combinations are permitted.

**Test-only misconception:** Because H2 is primarily used in test scope (`<scope>test</scope>` in Maven), many teams assume these vulnerabilities cannot affect production. This is partially correct: the Console is rarely started in production. However, a compromised build server or test pipeline can exploit the Console or JDBC URL attack surface against developer machines, artifact servers, and CI runners that start H2 as part of the test suite — all reachable environments with elevated supply-chain trust.

**Recommended posture:**
- Use H2 ≥ 2.2.220 (current stable series as of 2026).
- Never start the H2 Console with `webAllowOthers=true` without authentication (use the `-webAdminPassword` flag and modern OS process isolation so the flag is not visible to other users).
- Do not accept user-supplied JDBC URL strings in application code.
- In Spring Boot test configurations, prefer `spring.h2.console.enabled=false` (the default).

## Dependencies of Note

None flagged. H2 is pure Java with no security-relevant transitive dependencies.

## Open Questions

- H2 2.3.x (if released) — does it introduce new initialization APIs that revive the `INIT=RUNSCRIPT` attack surface?
- Are there additional XXE-class paths in H2's XML-handling code beyond `JdbcSQLXML.getSource()`?
- What is the adoption rate of H2 2.2.x vs 2.1.x and 1.4.x in active Spring Boot projects? Dependency scanners should flag any 1.x or 2.0.x usage immediately.
